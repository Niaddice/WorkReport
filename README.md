# WorkReport

Rust + Tauri 2 本地工作日报应用。前端使用 Vue 3、TypeScript 与官方 Material Web 组件，界面参考 Google Pixel / Material 3。首页采用模块化、可拖放的架构：界面元素是可独立复用的模块，用户可在运行时自由分栏、调整大小和放大查看，开发者也可通过模块注册表扩展新模块。

首页由可拖放的模块组成：日历、日报编辑、数据概览、历史记录、AI 总结、Excel报告、工作空间目录、Git 日报都可以关闭，但始终至少保留一个模块。竖向功能栏默认停靠在窗口最右侧，可在“设置 → 外观与字体”切换为左侧；它直接列出这些模块以及“布局”“皮肤”“刷新”：点击模块按钮会把对应模块加入分栏布局，已经存在时定位到该模块；“工作空间目录”模块以目录树展示工作空间下的所有文件（除 workreport.json 与隐藏文件外），目录可折叠/展开；其中形如 `<年份>/<yyyymmdd>.md|txt` 的日报文件可点击切换日期，日历、编辑、历史、总结与 Excel 模块都跟随该日期；`.xlsx` 文件可点击弹出预览；模块标题栏的关闭按钮可关闭模块，只剩一个模块时按钮隐藏。历史记录与默认合并内容在模块内展示，AI 总结和 Excel报告在各自的单个生成窗口中完成确认、进度和预览；点击“布局”可查看分栏操作提示或恢复默认布局。日历保留周一开头、相邻月份日期、今天定位、农历及节假日标记；月视图里补位的相邻月份日期只作参照，不能点击或框选。日历上方仅显示一行问候与当天日期。日历面板会随模块尺寸自动精简：窄于 480px 时隐藏农历、节日名和日报预览，日期数字居中并用圆点标记已记录；窄于 330px 时改用单字星期，进一步把工具栏折成两行；较矮的模块会压缩工具栏、页脚和日期留白。点击皮肤图标会弹出预览弹窗，点击卡片立即切换并保存；目前只有默认皮肤，新增皮肤需在 `src/lib/skins.ts` 注册并在 `style.css` 补对应的 `[data-skin='<id>']` 变量。设置以最大化弹窗覆盖主内容区，从侧边栏设置按钮展开；关闭时向窗口右上角关闭按钮收缩。未保存修改会先提示保存或放弃，确认后再关闭。顶部问候与日期、侧边功能栏保留，设置按钮高亮并固定在侧边栏最下方；再次点击设置按钮保存并关闭弹窗，点击模块/布局按钮会先关闭设置。设置按“基础设置”“AI 助手”“文件输出”分组；左侧切换工作空间、外观与字体、放假信息、数据存储、模型配置、生成提示词、总结文件和 Excel报告，右侧每次显示一个分类。未保存的分类显示圆点标记，切换分类会保留草稿。日报编辑支持撤销/重做和框选合并预览。

在“设置 → 放假信息”选择上一年、当年或下一年，点击“同步放假信息”手动更新中国大陆的放假及调休上班安排。数据来自 [holiday-cn](https://github.com/NateScarlet/holiday-cn)，完成后立即更新日历并保存到应用配置目录的 `holiday-data.json`，无需再保存设置；切换工作空间后继续使用，断网时沿用本地数据。下载、数据校验或保存失败会显示原因，保留上次成功同步的安排。桌面 App 提供同步，浏览器预览只读取本地预览缓存。

每年 1 月 1 日，应用读取当年的本地同步记录，未同步成功或最近一次同步失败时显示提醒，可进入放假设置同步，也可关闭当日提醒。应用跨年运行或重新获得焦点时沿用同一日期检查；1 月 2 日起不再提示。检查不会自动下载数据，原有内置节假日标记也不会被视为已同步。

桌面窗口最小为 960 × 680。顶部栏固定，首页模块板始终一屏展示并使用全部可用宽高，不出现滚动条；每个模块内部独立滚动。较矮窗口用圆点标记已有日报。正文、预览与设置内容在各自区域内滚动。

“设置 → 外观与字体”提供界面缩放步进控件，范围为 80%–120%，每次调整 10%，默认 100%，支持恢复默认。同一分类还可选择功能栏停靠在窗口右侧（默认）或左侧，保存后立即生效。缩放仅调整字体大小，可在示例区域预览，点击“保存设置”后应用到整个 App，重启后恢复已保存的选择。图标、面板尺寸与间距均不随缩放改变。全局字号统一使用语义标尺（以 1080p 下正文 12px 为基准，逐级区分标题、正文与灰色提示），全页字体随窗口大小自适应。

设置底部固定一个通用的“保存设置”按钮。界面缩放、数据存储、默认 AI、AI 配置与提示词、总结目录、Git 仓库配置及 Excel 模板与提示词的修改均先保留为草稿，点击后统一校验，并一次原子写入当前工作空间的 `workreport.json`，全部保存成功后生效。保存失败会保留草稿并显示错误；未保存的修改不会影响正在使用的配置。有未保存修改时，返回首页、切换工作空间或关闭窗口会弹出提示，可选择“保存并继续”“不保存”或“继续编辑”。“不保存”会放弃设置草稿，“继续编辑”会留在设置页面。

再次点击右下角已高亮的设置按钮，会保存当前设置并返回首页；没有修改时直接返回，校验或保存失败时保留设置页面和草稿。

页面、日历视图、编辑与预览、设置展开收起、模型输入方式及弹窗切换使用统一的轻量过渡；按钮提供悬停、按下及选中反馈。切换保留编辑状态，并遵循系统“减少动态效果”设置。

## 模块化首页与拖放分栏

首页由模块组成。所有模块都可以关闭，但至少保留一个模块；点击右侧功能栏中对应的模块按钮即可把模块加入分栏布局，已存在时按钮呈选中态并定位到对应模块。

模块边框高亮跟随用户当前点击或键盘聚焦的模块，日历也遵循相同规则。点击日历日期或目录中的日报只更新关联内容，保留当前模块的激活状态，不自动聚焦日报输入框；日报加载期间若点击其他模块，加载完成也不会抢走焦点。点击日报编辑区后才进入编辑。

编辑区右上角的格式和预览切换按钮旁提供“日报预览”开关，可打开或关闭独立悬浮窗口。窗口开启时按日报编辑模块左右的可用空间贴靠一侧，空间不足时自动收窄并保持在可视范围内。打开时从“日报预览”按钮展开，关闭时向预览窗口的关闭按钮收缩，最大化和还原时平滑调整位置与尺寸；手动拖动和拉伸实时跟随指针，并遵循系统的减少动态效果设置。拖动标题栏移动窗口，拖动右下角调整大小；标题栏支持最大化、还原和关闭。预览实时显示编辑区当前草稿或框选多日的合并内容，Markdown 按格式渲染，TXT 保留纯文本；单日 TXT 时不可开启。编辑区滚动会带动预览定位对应内容，修改正文或调整窗口大小后重新计算位置；悬浮窗口不占用分栏布局。

点击模块标题栏的问号图标，会在图标旁显示悬浮说明。点击说明窗外任意位置、再次点击问号图标或按 Esc 收起；切换到另一个模块的说明时会自动关闭前一个。

窗口动效统一从触发按钮处展开（约 360ms），关闭时向实际点击的关闭、取消或确认按钮收缩（约 280ms）；Esc 或遮罩关闭使用窗口的默认关闭按钮。皮肤、布局、确认框、Excel 预览、设置、日报悬浮预览和说明面板共用此行为。模块最大化与还原沿用模块区域之间的几何过渡。快速反向会接续当前位置，异步操作会保留按钮原始位置；系统开启“减少动态效果”时直接切换。

- **拖放分栏**：按住模块标题栏空白处或模块图标，拖到另一个模块上，会根据指针靠近的上/下/左/右半边显示“上方分栏 / 下方分栏 / 左侧分栏 / 右侧分栏”的预览；松开后把目标模块一分为二，拖动的模块插入对应一侧。标题与日期文字、帮助/放大/关闭等功能按钮不触发拖动，最大化时不可拖动模块。拖到两个模块之间的间隙时，会高亮插入位置并显示“插入此处”，松开后模块直接插到两者之间。拖到模块板最左或最右边缘时，会把模块放到整行最左或最右一列。`Esc`、拖出窗口或窗口失焦取消。所有模块都可以参与分栏和移动。
- **拖动间隙调整大小**：分栏之间的间隙保留透明拖动区域。拖动只改变接触该边界的模块：一侧为上下分栏时，上下模块同步调整宽度；内部还有左右分栏时，只调整贴近拖动边界的模块。非相邻模块的位置和尺寸保持不变，拖动预览与保存使用相同的实际尺寸和间距计算。左右分栏拖动可调整两侧宽度，上下分栏拖动可调整两侧高度；间隙获得焦点后也可用方向键微调。调整后的比例立即保存。
- **始终一屏**：模块板始终填满 App 可用高度，不出现滚动条。分栏越多每个模块越小，超出内容在模块内部滚动，不会把首页撑高。模块间隙为 `0.2rem`（默认约 3.2px），不显示拖动条，悬停在间隙时可按光标方向拖动调整大小；模块与 App 四周仍保留 `0.5rem`（默认约 8px）的留白。
- **布局记忆**：分栏是一棵可嵌套的布局树，保存在工作空间 `workreport.json` 的 `ui.layout` 中；旧版本的 `axis` / `order`、`columns` / `modules` 布局会在读取时自动迁移成默认分栏树。每次修改都会立即保存，切换工作空间时随工作空间切换，迟到的旧保存会被后端拒绝。
- 右侧功能栏的“布局”弹窗提供操作提示和“恢复默认布局”，还可把当前布局保存为命名快照，点击已保存布局一键切换或删除（快照随工作空间保存在 `workreport.json`）。
- 标题栏右侧的“放大”按钮会把模块放大到 App 整个可视区域，以悬浮层 + 遮罩显示，内容保持原有状态；放大时从原模块的完整区域平滑扩展，还原时回到分栏中的原位置和尺寸；模块保持可见，遮罩同步淡入淡出。再次点击、点击遮罩或按 `Esc` 还原；放大是临时视图，不写入工作空间布局。
- 布局树变化（分栏、增删、比例提交）使用 280ms FLIP 过渡；窗口尺寸变化（拖动缩放、最大化/还原）时，模块从当前画面矩形平滑缩放到新尺寸，约 160ms 缓动，连续拖动也不会硬跳；开启“减少动态效果”时直接切换。

新增模块不需要改页面编排层：在 `src/modules/types.ts` 的 `ModuleId` 中登记 id，创建一个通过 `useModuleContext()` 读取状态的组件，再在 `src/modules/registry.ts` 的 `MODULE_REGISTRY` 中注册元数据即可。模块 id 由后端按安全字符串存储，因此新增模块不需要修改 Rust schema。

## Git 日报与工作台

在“设置 → Git 配置”中添加本地项目仓库，可配置多个仓库、项目名称、作者姓名或邮箱筛选、分支以及是否包含合并提交。Git 程序默认使用本机 `git`，也可填写可执行文件的绝对路径。配置随当前工作空间保存到 `workreport.json`，统一点击“保存设置”后生效，切换工作空间时可随其他设置同步。

点击侧边功能栏的“Git 日报”打开模块，点击“获取提交”读取日历当前所选日期范围内的本地提交。范围完全跟随日历：框选多天时包含起止两天，支持跨月、跨年；未框选时读取当前选中的一天，点击“今天”可重置为当日。日期按本机时区和提交时间计算，作者按姓名或邮箱包含匹配且不区分大小写，分支留空时读取当前 `HEAD`，默认忽略合并提交。模块展示每条提交的摘要、作者、时间、哈希及完整说明，多日结果显示完整日期和时间。修改日历选择或工作空间会清空旧结果并丢弃旧请求，避免复用错误范围的记录。

多选日期时，预览按提交的本地日期拆分，每天的工作记录可分别编辑；点击“复制”会带日期标题复制全部分日预览。点击“追加到对应日报”把每一天的内容追加到该日期自己的日报中，保留已有正文及原有 Markdown / TXT 格式；没有日报时按当前默认格式创建，没有提交的日期不创建或修改日报。已追加的日期会标记完成，重试仅处理未完成日期；写入前会先保存当前编辑草稿，已有相同内容会跳过，失败按日期显示原因。单日仍提供“追加到当日日报”，并保留编辑区撤销功能。

日报功能无需配置 AI，读取本地已有记录；远端提交可以先在「Git 工作台」中 Fetch 或 Pull。单个仓库读取失败时会显示原因，其他仓库仍可使用；每个仓库在所选日期范围内最多展示 1000 条提交，超出时提示缩小日期、作者或分支范围。

在模块上方切换到「Git 工作台」，选择已配置的仓库，即可使用以下功能。日报的作者、分支、日期及合并提交筛选不影响工作台，工作台始终显示实际检出的分支和仓库状态。

- **本地变更**：分组查看暂存、未暂存、未跟踪及冲突文件，选择文件查看对应 Diff；支持单个或批量暂存、取消暂存。填写提交说明后只提交暂存区内容，保留未暂存修改；冲突未处理完成时阻止提交。丢弃操作只恢复所选文件的未暂存修改，执行前会显示确认。
- **历史**：按提交说明搜索，选择当前分支、其他分支或所有分支，分页浏览提交的作者、时间、哈希、引用和完整说明，查看提交 Diff，并复制提交哈希。
- **分支**：查看本地和远程分支，创建并切换分支、切换已有分支、删除已合并的本地分支、快进合并其他分支。删除分支前需要确认，未合并分支由 Git 阻止删除。
- **Stash**：将当前修改连同未跟踪文件保存为 Stash，支持应用、弹出和删除。删除前需要确认；应用或弹出失败会显示 Git 错误，冲突文件会显示在变更列表中。
- **远程同步**：显示当前上游、领先和落后的提交数；Fetch 更新远程引用，Pull 仅执行快进更新，Push 按上游正常推送。使用本机已有的 SSH 或凭据配置；需要交互认证、未配置上游或分支已分叉时会显示错误，处理后可重试。

Git 工作台需要在桌面应用中运行。操作完成后自动刷新仓库状态，并清空旧的日报提交结果；切换仓库或工作空间时会清除之前的状态和 Diff，避免把旧结果用于另一个仓库。Diff 有输出大小上限，超限会明确提示。

修改 Git 配置后，保存时会根据实际 Git 公共目录和主要远程地址检查重复：同一仓库的子目录、符号链接、worktree，以及同一远程仓库的多个本地克隆不能重复添加。主要远程优先使用 `origin`，没有 `origin` 时使用唯一的远程；SSH、HTTPS、可选的 `.git` 后缀等常见写法会统一比较，保留仓库路径大小写和自定义端口，避免误合并不同项目。不同 fork 仅共享上游地址不会被判为重复。已有配置在获取提交时还会按仓库身份和提交哈希去重，并显示跳过数量，保留各来源的独有提交。保存配置的检查只读取本地 Git 信息，不访问远程服务器；工作台仅在点击同步操作时连接远程。

## 提示与消息

所有全局瞬时提示统一显示在窗口顶部的 Message 区域：保存失败、数据库备份提醒、布局保存失败、工作空间错误，以及设置保存、数据库连接、放假同步等成功反馈。Message 区分成功、信息、警告和错误样式，默认自动消失，也可手动关闭；错误和需要处理的消息会附带操作按钮（例如“重试保存”“重试数据库备份”）。同一时间最多显示 4 条，相同文案会合并刷新，不重复堆叠。模块拖放、分栏、插入间隙等成功操作不弹顶部 Message，只通过模块板内的无障碍播报反馈。表单字段校验和对话框内的错误仍保留在对应控件或弹窗内。

## 日报与工作空间

1. 首次启动时选择文件夹作为工作空间；之后启动会自动打开上次选择的工作空间，直接进入日报界面。没有历史工作空间或目录无法打开时，显示工作空间选择页；打开失败的原因会保留在页面上，可以重试上次的目录或重新选择文件夹。
2. 单击日期查看或开始新日报；没有日报的日期直接显示空编辑区，新日报默认使用 TXT 纯文本，可在“设置 → 数据存储”改为 Markdown，也可在编辑区临时切换。已有日报保持原格式。输入内容后自动创建文件并保存，不再弹出新增确认。
3. 在周、月、年视图中按住鼠标拖拽可框选连续日期。每次拖拽会替换之前的框选范围；单击日期查看当天日报。切换周/月/年视图时保留当前框选，切换上一/下一时段时清空框选。框选后右侧编辑区平滑切换为只读合并预览，按日期降序显示所选范围内已有内容的日报；标题使用简化日期，跨年选择时显示年份；过长时省略并在悬停时显示完整区间。按 `Esc` 或重新选择日期退出。合并预览仅保留原文/预览切换，汇总统一在“AI 总结”模块中操作：从右侧功能栏打开模块，点击日期行右侧的 AI 图标，选择“AI 总结”或“直接总结”。模块自动读取框选范围内实际存在的日报，范围中包含无日报日期时仍可使用；没有可总结内容时两项功能置为不可用，不弹无内容提示。直接总结按日期合并纯文本，日期行不含星期，条目按 1、2、3 编号，不同日期之间空一行。总结不会创建或修改日报文件。
4. 默认以文件保存，位于工作空间的年份子目录，以 `<年份>/yyyymmdd.md` 或 `<年份>/yyyymmdd.txt` 命名。已有文件会直接打开。也可在“设置 → 数据存储”启用数据库双存储，或将日报迁移到数据库存储。
5. 停止输入 650ms 后自动保存，也支持 `⌘S` / `Ctrl+S`。切换日期、工作空间或关闭窗口前会先保存。编辑区支持撤销/重做：macOS 使用 `⌘Z` / `⌘⇧Z`，Windows 使用 `Ctrl+Z` / `Ctrl+Y`（也支持 `Ctrl+Shift+Z`）。同一篇日报内容未变时，刷新或返回应用会保留撤销历史；切换日期/工作空间、读到外部修改或明确重新载入后重置。内嵌 AI 总结和 Excel 模块不影响日报快捷键。
6. 已有日报的 Markdown / TXT 开关会先请求确认，再更换文件扩展名；新草稿切换只改变待创建文件的扩展名。正文逐字保留，不删除 Markdown 标记，不覆盖已经存在的目标文件。
7. “复制”文字操作把当前编辑器的全部正文复制到系统剪贴板，包括尚未自动保存的编辑。
8. 在“设置 → 工作空间”切换文件夹。选好新文件夹后，可选择“同步并切换”，把当前已保存的字体、AI 配置与提示词、输出、数据存储、布局和皮肤设置同步过去并覆盖目标对应设置；选择“仅切换”则保留目标自己的设置，“取消”留在原工作空间。同步只复制设置，不复制原工作空间的日报；目标保留独立的数据库标识。已有未保存设置时，会先提示保存或放弃修改。首次选择工作空间和启动时自动恢复不显示同步确认。点击首页左下角路径旁的文件夹图标，可在系统文件管理器中打开当前工作空间。点击右侧功能栏的刷新图标重新读取当前存储中的日报；返回应用时也会自动刷新无修改的日报。
9. Markdown 工具栏提供标题、加粗、无序列表和待办；点击“更多”可插入斜体、删除线、有序列表、引用、行内代码、代码块、链接、分隔线和表格。选中文字后应用到选区，多行列表/引用会逐行处理；空选区提供占位文字。每次格式操作可独立撤销，预览状态点击工具会返回编辑模式。

```text
你的工作空间/
├── .history/
│   └── 20261018/
│       └── 1729756800000-1a2b3c4d.md
├── 2026/
│   ├── 20261018.md
│   └── 20261019.txt
├── 2027/
│   └── ...
└── ...
```

文件存储时，日历索引只扫描文件元数据；某个月的预览在显示该月时按需读取，并缓存在内存中。保存成功后只更新当前日报的索引和预览，不再重新扫描整个工作空间。同一天只保留一个日报文件：已有任一格式时不会创建另一种格式；若外部同时存在两种格式，索引优先使用 `.md`。新日报在输入内容前不会创建文件，复制图标隐藏，AI 按钮不可用；输入内容后自动创建并保存，格式切换只改变待创建文件的扩展名。仅数据库模式下，日历、预览及编辑通过数据库读取和保存日报。

每次成功保存都会在 `.history/<日期>/` 下留一份版本快照（内容相同不重复写入）。历史版本默认上限为 1 GB，可在“设置 → 数据存储”用滑块调整（1–10 GB，每格 1 GB）；超过上限时从最旧的一天开始整天清理，单日最多保留 100 份。右侧功能栏的“历史记录”可添加历史记录模块：选中单个日期时列出当天的历史版本；框选日期范围时按日期分组显示每天的版本。鼠标指向或键盘聚焦某个版本时，会在指针附近显示该版本完整内容的 tooltip，记录右侧同时显示复制图标，点击可复制对应历史版本的完整原文，成功后显示勾选反馈。历史快照始终保存在工作空间文件中，即使启用仅数据库存储也不会写入数据库，因此切换工作空间时历史随之切换。

当前暂时禁用整个应用的右键菜单，原有菜单功能代码保留；文本复制快捷键仍可使用。后续可将 `src/lib/contextMenus.ts` 的 `CONTEXT_MENUS_ENABLED` 改为 `true` 恢复。

日报正文默认保存在工作空间文件中，可选 SQLite、MySQL 或 PostgreSQL 数据库存储，不使用浏览器存储。应用配置目录只保存最近工作空间路径；界面缩放、数据库连接、AI 配置、总结输出和 Excel 输出设置保存在工作空间根目录的 `workreport.json`，切换工作空间会同步切换这些设置。旧版本的 `ai.json`、`appearance.json` 仅在 `workreport.json` 尚未创建时作为回退读取，首次保存后不再使用。其他非日期文件不会被修改。日期文件需为 UTF-8 编码；非 UTF-8 文件仍会出现在日历索引中，但无法预览或打开，请在外部编辑器转码后再使用。若其他编辑器改动了同一文件，保存会报告冲突并保留草稿，可复制草稿后重新载入。

当前版本按年份目录存储，不读取根目录下旧版扁平日期文件；本项目暂不提供旧布局迁移。

## 数据库存储与迁移

打开“设置 → 数据存储”，开启“启用数据库存储”后点击底部“保存设置”。默认选择 SQLite、文件与数据库双存储，在当前工作空间创建 `workreport.sqlite`，并将现有日报作为首次备份写入数据库。也可使用工作空间内的其他相对路径，扩展名支持 `.sqlite`、`.sqlite3` 或 `.db`。同一页面还可设置新日报的默认格式（Markdown 与纯文本，只影响之后新建的日报）和历史版本存储上限（默认 1 GB）。设置仍需手动保存，测试连接不会提交设置。

支持以下三种日报存储状态：

| 状态                   | 日报读取与保存行为                                                       |
| ---------------------- | ------------------------------------------------------------------------ |
| 文件存储（关闭数据库） | 从工作空间读取并保存 Markdown / TXT 日报。已有数据库及其中的数据保留。   |
| 文件与数据库双存储     | 继续以日报文件作为读取来源，每次保存文件后同步写入数据库。               |
| 仅数据库               | 从数据库读取并保存日报，原有日报文件保留，后续修改不再自动写入这些文件。 |

双存储时，数据库不可用不会把已经成功的文件保存显示为失败。界面会单独提示数据库备份失败，并可独立重试备份；未完成的备份应在恢复连接后重试。仅数据库模式下，数据库写入失败会保留编辑草稿并显示保存错误。

MySQL 与 PostgreSQL 需先在服务器上创建数据库，并配置具有建表、读取和写入权限的用户。在设置中填写主机、端口、数据库名称、用户名、密码和 TLS 方式；端口为 `0` 时，MySQL 使用 `3306`，PostgreSQL 使用 `5432`。应用会在已存在的数据库中创建所需数据表，通过工作空间标识区分不同工作空间的日报。可点击“测试连接”检查当前输入，随后点击统一保存按钮使配置生效。数据库密码保存在本地工作空间的 `workreport.json` 中，未加密；连接错误会隐藏密码。

“复制与迁移”使用已保存的数据库配置，设置存在未保存修改时需先保存。选择“日报文件 → 数据库”或“数据库 → 日报文件”后：

- **复制**：将日报复制到目标，保持当前存储方式。
- **迁移到数据库**：复制并核对成功后，切换为仅数据库读写，保留原日报文件。
- **迁移到日报文件**：复制并核对成功后，关闭数据库存储，切换为文件读写，保留数据库中的原数据。关闭后仍可通过保存过的连接配置复制或重新迁入。

同日期、同格式且内容一致的日报会跳过。默认遇到同日期、不同内容或格式的日报就停止，不覆盖目标；如需以源数据更新目标，选择“覆盖目标内容”，并在执行前的确认区勾选覆盖确认。迁移会在复制结果核对完成后切换存储方式，源数据不会被删除。

数据库备份和迁移仅处理日报的日期、正文与 Markdown / TXT 格式，不包含 `workreport.json`、Excel 模板、总结及 Excel 导出文件。此功能使用应用自己的数据库表结构，不自动导入其他应用或历史版本的任意 SQLite 数据库。

## AI 设置与生成

在“设置 → 模型配置”配置。选择默认 AI、添加或移除模型以及修改提示词后，统一点击底部“保存设置”提交；退出设置时可按提示保存或放弃修改。支持以下配置：

- **本机 CLI**：“检测本机 CLI”检测 Codex、Claude Code、OpenCode；支持常见 PATH、Homebrew、用户安装目录、NVM，以及 macOS Codex / ChatGPT 客户端内置的 Codex CLI。检测只查询版本，不调用模型。添加后可编辑 CLI 路径及可选模型 ID；Codex 和 OpenCode 可点击“获取模型”，分别通过 `codex debug models` 和 `opencode models` 读取可用模型并选择，失败或列表为空时仍可手动填写。Claude Code 不提供机器可读模型列表，请手动填写或留空使用 CLI 默认模型。需先在终端完成该 CLI 的登录。
- **模型接口**：支持 OpenAI（Chat Completions）兼容 API 与 Anthropic（Messages）兼容 API，内置 DeepSeek、Gemini、Anthropic 预设及自定义服务。填写接口地址、API Key（本地免密接口可留空）后，点击“获取模型”读取模型列表并选择，也可手动填写模型 ID。OpenAI 兼容接口可填基础地址或完整 `/chat/completions` 地址；Anthropic 兼容接口使用 `/messages` 端点，填写如 `https://api.anthropic.com/v1`。获取列表沿用当前填写的密钥，无需先保存；重新获取不会自动替换已选模型，更换地址或密钥会清空旧列表。所选模型随 AI 设置保存，获取失败或列表为空时仍可手动填写。
- **默认 AI**：由用户手动选择一个；添加和检测不会自动选择。也可使用“暂不设置默认 AI”。
- **AI 提示词**：在“设置 → 生成提示词”分别填写“日报润色提示词”和“框选总结提示词”，各最多 2000 字。提示词会追加在固定的事实、安全和格式规则之后，对所有 CLI 和模型接口生效；留空时使用默认规则。旧的“AI 生成倾向”会作为日报润色提示词保留，沿用同一套 AI 设置保存逻辑。

常用基础地址：

| 服务            | 基础地址                                                  |
| --------------- | --------------------------------------------------------- |
| DeepSeek        | `https://api.deepseek.com/v1`                             |
| Gemini 兼容接口 | `https://generativelanguage.googleapis.com/v1beta/openai` |
| 自定义服务      | 服务商提供的兼容接口地址                                  |

框选总结只将所选日期中已有内容的日报交给默认 AI。CLI 在独立临时目录中运行，不把工作空间作为工作目录。Codex CLI 总结使用低推理模式，并跳过与总结无关的插件、MCP 服务和通知钩子，以缩短启动和等待时间。

框选总结统一使用“AI 总结”模块，模块打开后自动读取所选范围的日报并默认直接合并。直接合并无需配置 AI，也不发出 AI 请求：每个日期块以日期开头，条目按 1、2、3 编号，续行缩进，不同日期间空一行。点右上角“总结”按钮直接打开一个生成窗口，顶部展示完整日期范围、默认 AI 和实际日报天数，中间可临时编辑本次总结提示词。提示词从设置复制，留空设置时展示默认总结规则；临时修改不写回设置，重新打开时恢复。点击“确认并生成”才调用 AI，在同一窗口查看处理进度、耗时和 Markdown 结果，并可复制或导出 Markdown/TXT。可返回修改提示词后重新生成，失败后保留本次编辑供重试；取消会停止当前请求，迟到的结果不会覆盖新请求。未配置 AI 时，窗口内提供配置入口。生成结果同时显示在模块中，日报原文不变。

API Key 随 AI 配置保存在工作空间根目录的 `workreport.json` 中；Unix 文件权限为 `0600`，未写入日报或日志，未加密。HTTP 请求在 Rust 中发出，拒绝自动跳转，错误信息不会回显服务商响应中的敏感内容。CLI 使用其已有账号与计费配置。Claude Code 和 OpenCode 的适配已实现，实际可用性取决于本机安装、版本及登录状态。

参考：[Codex 非交互调用](https://learn.chatgpt.com/docs/non-interactive-mode)、[Claude Code CLI](https://code.claude.com/docs/en/cli-reference)、[OpenCode CLI](https://opencode.ai/docs/cli/)、[DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)、[Gemini 兼容接口](https://ai.google.dev/gemini-api/docs/openai#list-models)。

## 总结输出

在“设置 → 总结文件”配置工作空间内的总结子目录，默认 `summary/`，也可填写如 `summary/周报` 或选择已有子目录。输入、选择或恢复默认目录后，点击底部“保存设置”才会保存并生效。配置随工作空间保存在 `workreport.json`，目录会在首次打开或导出时自动创建。

生成结果后，通过 AI 总结模块日期行右侧的复制图标复制文本，或点击相邻的导出图标，选择 Markdown 或 TXT 保存到已配置的总结目录。模块内不再显示目录路径。文件名使用 `总结_YYYYMMDD-YYYYMMDD_YYYYMMDD_HHMMSS.md|txt`，日期范围包含框选内没有日报的起止日期；导出时间使用本机时间，同秒重名时追加 `_1`、`_2`，保留已有文件。旧默认目录“总结”自动改用 `summary/`，其他自定义子目录继续生效。Markdown 保留结果原文；AI 总结导出 TXT 时转换为可读纯文本，直接总结导出 TXT 保留原有编号和换行。导出失败会在模块内显示原因，成功后顶部 Message 也会提示文件名。

## Excel 输出

在“设置 → Excel报告”开启功能。开启前需配置并选择默认 AI；开启后显示模板和输出提示词，填写后点击底部“保存设置”，与其他设置一起保存并生效。模板支持 `.xlsx` 文件，提示词最多 6000 字，例如：把本周已完成工作填入“周报”工作表 B5，把问题与下周计划分别填入 B8、B11，保留标题及未填写区域的公式。

提示词旁的“使用推荐设置”可一键填入按项目分类提炼成果的模板规则：F2 使用所选范围最后日期（YYYYMMDD），第 14 行开始按 A–K 列填写序号、项目分类、开发、功能正常、F2 日期、张三、预估工时、进行中、李四、成果明细和空白；总工时为工作日数乘 8，D11 为工时总和，B11 为任务数量，明细区域使用黑色边框，多个子任务换行显示。点击后可继续编辑，保存设置后生效。

在日历选择单日或框选日期范围后，点击功能栏“Excel报告”添加模块。生成使用实际选中的单日或整个范围，支持跨周、跨月、跨年，不再限制为一周或七天。已导出列表自动显示与所选日期有交集的报告，边界日期也计入；从工作空间目录切换单日日报时同步更新。原有“周报”文件名仍可识别，无法识别日期范围的文件继续显示。

已导出区域右上角提供生成 Xls、打开目录和刷新三个悬浮图标。点击 Xls 直接打开一个窗口，顶部展示日期、默认 AI 和 Excel 模板，中间显示可编辑的本次提示词；默认从设置复制，临时修改不会同步到设置，关闭后恢复。点击“确认并生成”才调用 AI，同一窗口依次显示处理进度与耗时、填充预览。生成后可展开查看本次提示词，也可点击“修改提示词并重新生成”回到编辑步骤。取消或 Esc 不会在确认前调用 AI；生成中可关闭窗口取消，失败后保留本次提示词及日期供修改重试。核对后点击“确认输出”才保存文件，直接使用已预览的工作簿，不再次调用 AI。生成预览、返回或取消均不会创建输出文件。范围内至少需要一篇非空日报，没有日报的选中日期仍计入范围。配置不完整时，窗口内提供 Excel 设置入口。

预览默认显示填充后的工作表网格，包含模板标题和原有内容，保留列宽、行高、合并单元格、字体、配色、边框、对齐及数字格式，并按模板隐藏行列。可切换工作表、缩放表格、选中单元格查看内容或公式，也可切换“填充明细”核对本次写入及格式设置。较大或稀疏的表格按区域展示，并提示未完整显示的模板范围。预览不重新计算公式，使用文件中的已有结果，无已有结果时显示公式；图片、图表等绘图元素暂不显示。

生成预览时，应用使用窗口内确认的本次提示词（默认来自“设置 → Excel报告”），将所选日期的日报原文与模板中的工作表、单元格信息交给默认 AI，整理内容并生成填表结果。该过程独立于 AI 总结模块中的生成。应用在内存中的模板副本上完成填充、格式处理及文件校验；需要填写的单元格若已有公式，会替换为 AI 返回的静态值，并在预览中标记。未另行指定修改的模板样式、合并区域及未填写单元格的公式保留，原模板和已有输出文件均不会被覆盖；若程序无法替换公式，会提示清除对应模板单元格的公式后重试。生成过程中可关闭模块；确认保存期间按钮暂停操作。确认前如果工作空间、所选日报、Excel 设置或模板已经改变，需重新生成预览；预览保留 30 分钟。完成后刷新 Excel 模块中的已导出列表，并可打开 Excel 输出目录；报告固定保存到当前工作空间下的 `excel/` 目录，目录不存在时自动创建。确认输出时按本机当前时间命名为 `总结_YYYYMMDD-YYYYMMDD_YYYYMMDD_HHMMSS.xlsx`，与 Markdown/TXT 总结共用规则，同秒重名时追加递增序号。旧设置中的自定义 Excel 输出目录不再使用，已有文件保留在原处。原日报不会被修改。旧版 `.xls` 模板请先用 Excel 另存为 `.xlsx`。

提示词支持为指定区域设置黑色细实线四边框、自动换行和按内容增高行高。例如：“第 14 行开始的明细区域使用黑色边框，自动换行并按内容调整行高。”AI 会给出实际明细范围，应用在写入内容后设置格式；未指定区域沿用模板格式。行高根据列宽、字号和中英文内容估算，保留模板中已有的更高行高。最多支持 32 个格式区域，填充值与格式区域合计不超过 5000 个单元格，不接受整行、整列或无限范围。

## 开发与构建

需要 Node.js 22.12+、npm、Rust 1.90+ stable，以及 [Tauri 平台依赖](https://v2.tauri.app/start/prerequisites/)。macOS 需要 Xcode Command Line Tools。

```sh
npm ci
npm run app:dev
```

```sh
npm run build          # TypeScript 检查及前端构建
npm test               # 日历、模块布局与拖放、设置草稿、存储配置、保存、格式切换及 AI 预览生命周期
npm run test:rust      # 文件边界、数据库存储、格式切换、AI 配置与本地模拟接口
npm run lint           # ESLint（Vue 3 + TypeScript）
npm run format         # Prettier 格式化
npm run verify         # lint、格式检查、构建与前端测试一次跑完
npm run app:build      # 桌面安装包
```

推送与合并请求会执行 `.github/workflows/ci.yml`：前端规范检查、类型检查、构建与单元测试，以及 Rust 侧单元与集成测试。

macOS `.app` 输出到 `src-tauri/target/release/bundle/macos/`。`npm run dev` 仅提供浏览器界面预览；工作空间、剪贴板、CLI 和 AI 设置需要 Tauri 桌面环境。

## 一键提交与发布

仓库固定为 [Niaddice/WorkReport](https://github.com/Niaddice/WorkReport)。`release.sh` 与 `release.command` 只保留在本地，已在 `.gitignore` 中排除、不随仓库分发；从仓库克隆后需要自行准备这两个脚本才能使用本节流程。

安装 Git、GitHub CLI（`gh`）及上面的构建依赖，首次使用时登录，并确认已配置 Git 提交身份：

```sh
gh auth login --hostname github.com
git config --global user.name "你的姓名"
git config --global user.email "你的 GitHub 邮箱"
```

在项目中执行一个命令；macOS 也可以在 Finder 中双击 `release.command`：

```sh
./release.sh
```

脚本会连接已有仓库、同步版本号、安装依赖、提交更改、运行前端和 Rust 测试、构建安装包、生成 SHA-256 校验和，再推送当前分支及标签并发布 GitHub Release。首次连接时沿用远端默认分支和提交历史，保留本地现有文件，并恢复远端独有文件。已有 Git 仓库使用当前分支；远端有尚未合并的提交时会停止，需先自行同步。

所有未被 `.gitignore` 忽略的更改都会提交，包括新增文件和删除。版本会同步到 `package.json`、`package-lock.json`、Tauri 配置、`Cargo.toml` 和 `Cargo.lock`。默认沿用项目版本；标签或 Release 已存在时自动递增补丁版本。指定的版本已存在时会报错，不覆盖已有发布。

```sh
./release.sh --dry-run                     # 离线预览，不修改任何文件
./release.sh 0.1.1                         # 指定版本
./release.sh 0.1.1 -m "优化模型选择"         # 自定义提交说明
./release.sh --notes-file release-notes.md  # 从文件读取发布说明，默认自动生成
./release.sh --draft                       # 上传草稿，留待手动发布
./release.sh --resume v0.1.1                # 推送/上传失败后，使用原产物重试
```

产物保存在 `.release/v版本号/`，不会提交到仓库。仅构建当前电脑的平台和架构：macOS 上传包含完整 `.app` 的 ZIP；Linux 上传 DEB 和 AppImage；Windows 在 Git Bash 中执行，上传 MSI 和 EXE。macOS 默认使用 ad-hoc 签名，Developer ID 签名与公证配置见下方“macOS 安装与签名”；Linux 和 Windows 安装包沿用项目及本机的 Tauri 签名配置。

测试或构建失败时不会推送，但本地版本修改和已完成的提交会保留。推送、上传失败时，按提示使用 `--resume`：脚本会核对提交、分支和安装包校验和；已存在的草稿可继续上传，正式 Release 的附件保持原样。重试沿用原来的草稿模式，不需要重新构建。脚本不强制推送；多个发布进程通过 `.release/.publish.lock` 互斥。

脚本自身的集成测试使用临时 Git 仓库和模拟 GitHub/构建命令，全程禁用网络传输；运行它需要 Python 3：

```sh
npm run test:release
```

## macOS 安装与签名

macOS 打包默认使用 ad-hoc 签名（`src-tauri/tauri.conf.json` 的 `bundle.macOS.signingIdentity` 为 `"-"`），因此本地构建会带上有效签名，不再因为缺少签名被 macOS 判定为“已损坏”。重新执行 `npm run app:build` 或 `./release.sh` 后生效。但 ad-hoc 签名没有经过 Apple 公证，从浏览器或 GitHub 下载后首次打开仍可能被 Gatekeeper 拦截。把 `WorkReport.app` 拖入“应用程序”后执行一次：

```sh
xattr -dr com.apple.quarantine /Applications/WorkReport.app
```

然后正常打开。旧版 macOS 也可以右键选择“打开”；macOS Sequoia 及以上可能还需要到“系统设置 → 隐私与安全性”点击“仍要打开”。只需要处理一次。

如果要发布给其他人、并让首次打开不出现任何拦截，需要使用 Apple Developer ID 签名并公证。`release.sh` 支持 Tauri 的签名/公证环境变量：

```sh
APPLE_SIGNING_IDENTITY="Developer ID Application: 你的名称 (TEAMID)" \
APPLE_ID="you@example.com" \
APPLE_PASSWORD="App 专用密码" \
APPLE_TEAM_ID="TEAMID" \
./release.sh
```

也可以使用 App Store Connect API Key：`APPLE_API_KEY`、`APPLE_API_ISSUER`、`APPLE_API_KEY_PATH`。证书不在本机钥匙串时，再设置 `APPLE_CERTIFICATE` 和 `APPLE_CERTIFICATE_PASSWORD`。配置 Developer ID 后，脚本会用 `codesign` 和 `spctl` 校验签名与公证结果；未通过会中止发布，避免上传有问题的安装包。签名配置变更后请重新构建发布；`--resume` 会复用 `.release` 中的旧产物。参考 [Tauri macOS 签名文档](https://v2.tauri.app/distribute/sign/macos/)。

## 源码

架构、保存链路与设计取舍见 [ARCHITECTURE.md](ARCHITECTURE.md)。

- `src/App.vue`：页面编排；`AppToolbar.vue`：问候与工具栏；`WorkspaceGate.vue`：工作空间引导页。
- `src/components/MessageHost.vue`：顶部 Message 提示；`src/lib/messages.ts`：提示队列、自动关闭与操作。
- `src/components/ModuleBoard.vue`：分栏布局几何、拖放预览、间隙拖动与最大化；`ModulePanel.vue`：模块外壳；`LayoutDialog.vue`：分栏操作提示与恢复默认。
- `src/modules/registry.ts`：模块注册表；`src/modules/context.ts`：模块运行上下文；`src/modules/layout.ts`：分栏树归一化、旧布局迁移、几何切分与拖放命中计算。
- `src/components/modules/`：日历、日报编辑、数据概览、历史记录、AI 总结、Excel报告等模块内容组件；历史记录/总结在模块中展示，Excel 通过 `ExcelPreviewDialog.vue` 弹出生成与确认窗口。
- `src/components/CalendarPane.vue`：日历；`JournalEditor.vue`：两种格式编辑和文字操作；`RangeOverview.vue`：框选合并预览。
- `src/components/SettingsView.vue`：设置分类、手动统一保存；`DatabaseSettings.vue`：数据库连接与复制迁移；`ConfirmDialog.vue`、`SettingsLeaveDialog.vue`：二次确认。
- `src/lib/useJournal.ts`：串行自动保存、文件格式切换和草稿保护；`src/lib/ai.ts`：AI 设置、请求及取消。
- `src-tauri/src/workspace.rs`：按年目录索引、元数据缓存、按需预览、原子保存和格式切换，拒绝路径穿越、符号链接及重复格式。
- `src-tauri/src/ui.rs`：模块化界面偏好（分栏树、皮肤）及旧布局迁移。
- `src-tauri/src/ai.rs`：CLI 检测与调用、配置持久化、自定义 HTTP 接口及超时取消。
- `src-tauri/src/settings.rs`：工作空间设置的读写与原子保存（`workreport.json`，界面与 AI 共用一份文件）。
- `src-tauri/src/database.rs`：SQLite、MySQL、PostgreSQL 连接、工作空间隔离和日报读写。

Excel 模板输出已支持；邮件配置、独立的报告风格与模板管理、其他报告生成配置尚未包含。节假日可在“设置 → 放假信息”手动同步，未同步年度继续使用内置安排。
